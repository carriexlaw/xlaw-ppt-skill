## 08-comparison.md

## 对比表达

适用：

- A vs B
- Before / After
- Old / New
- Options
- Competitors
- Feature comparison

### Layout Patterns

- Two-column
- Comparison table
- Before / After
- Hero winner + alternatives
- Spectrum

### Rules

- 对比维度一致
- 差异必须快速识别
- 如果存在明确优劣，需要视觉体现；有明显对比含义的内容必须有视觉区分
- 优劣势的写法
  - 优势：accent 圆形标题容器（`tag`）+ accent 描边框（`card:N`）+ accent 面性 icon
  - 劣势：深灰圆形标题容器 + 深灰描边框 + 深灰面性 icon
  - 框内每条要点前配语义面性 icon，句尾不加标点
- 方案页：第一层级是每个方案的标题，不是某个方案里的数字
  - 胶囊「方案一 / 二 / 三」（`tag`）+ 方案名小标题级 accent（`heading`）+ bullet
  - 推荐项用 tertiary 浅色填充卡，其余用中性浅灰填充卡
  - 高亮色全部集中在推荐项：只有推荐项的方案名、胶囊、bullet 圆点、关键数字用 accent；其余方案的方案名用深色、圆点用深色、数字不高亮
  - 方案名、决策句用 Medium，不用 Bold
  - 管理层决策句放在卡片下方，小标题级深色（`conclusion`）
  - 方案里的数字（如 35%）留在该方案的要点里加粗高亮
- 避免左右信息量严重失衡
