## 01-visual-foundations.md

全局视觉规则

### Visual Hierarchy

- 每页只能有一个核心的dominant message
  - 即要表达的核心观点只能有一个
  - 但这个核心观点可以有多个分论点
  - 分论点太多则分成两页/多页
  - 不允许所有元素同时强调
- 大小、明度、颜色、位置共同决定视觉权重

- 第一层级 = 本页论述对象；它可以是一组，不必是一个
  - 生成前先回答「这一页在讲谁」，写进 manifest 的 `focus.object`，再选 `focus.form`（见 00 Step 3）
    - 讲客户 → 客户类型；讲三个方案 → 三个方案名；讲一个选址的三项关键指标 → 三个数字一起；讲落地路径 → 时间线本身，关键节点高亮；讲趋势 → 图表 + 结论句
  - 大数字只有在数字本身就是论述对象时才进第一层级；它只是某个对象的属性时，留在该对象的要点里加粗高亮
  - 有几个重要数字就一起强调几个（上限 4），不挑一个；同组并列项同字号、同字重、同颜色、同对齐 [M]
  - 第一层级承载本页结论，不是装饰：大数字必须是标题那个判断的证据，图表必须支撑标题 [J]

- 字号分级（b = 本页正文字号，取 type_scale 里最近的值）

  | 层级 | 内容 | 字号 | 样式 |
  |---|---|---|---|
  | 大标题 | title | 轻 / 中页 36–40，重页 28–32；必须单行；过长（墨迹宽 > 84% 标题宽，占了大半页宽）就缩一档，可低于该档 | 中文 Bold；字间距内容页 7.5%（约 3pt），封面 / 章节 / 目录 10% |
  | 大数字 | 是论述对象的数字 | 2.5–3.2 b，内容页上限 54 | 英文字体 Bold；结论数字 accent，论据数字深色（secondary）；单位紧跟数字，小一到两档，同色同字重 |
  | 数字释义 | 紧贴大数字右侧，或在数字正下方（释义比格子宽、并排多个数字时放下方） | 1.1–1.8 b，1–2 行，右侧时总高 ≤ 数字高 | 深色 Medium / 细体，不用 accent |
  | 小标题级 | 论述对象名、方案名、分类名、结论句、图表标题 | 1.25–1.8 b | Medium（不用大标题同款 Bold）；accent（> 20 字用 secondary；图表标题用深色不用 accent）|
  | 正文 | 要点、说明 | 轻 18–20 / 中 16 / 重 14 | Light（细体）|
  | 小字 | source、口径、注释 | 10.5–12 | 灰 |

- 重点与论据分开（第六轮）：先判断本页哪一块是结论 / 观点、哪一块只是事实 / 现象 / 论据
  - 结论要大、要占面积；论据缩小退后。「获客成本两年翻倍」是现象，「原因有三个」才是这一页的重点：原因放左侧主区、放大、配小标题与 icon；数据收进右侧区域容器
  - 重点内容只有一句话 / 一对数字时放进区域容器是合理的，但容器不能太小：结论区的面积要与它的重要性相称
  - 论据数字用深色或低饱和色，高亮色只留给结论里最重要的那个数字（P5：中间四项规模指标是论据 → 深色；底部 18% 是「增速腰斩」的核心 → accent）
- 数据必须带着解释才有意义
  - 每个数据配小标题级的名称（「单个注册团队 获客成本」），放在数字上方或下方；只放大数字、把名称留在小字里，等于没有可视化
  - 单位不藏进小字：单位紧跟数字、与数字同色同字重、字号小一到两档（48.6 万、2.34 亿、4.5 个月）；layout.py 的 text 节点用 `unit` 字段
  - 两个数字的对比要把对比的维度写出来：是两个时间就把时间标在各自数字上方（2025.9 / 2026.9），不能只有「46% → 18%」
  - 「加粗大数字 + 箭头」不要频繁使用：全 deck ≤ 3 页；其余对比用小表格、成对条形图、前后两列等方式
- 不许断层 [W]：页面上有大数字时，必须同时有数字释义或小标题级文字；最大字号（title 除外）/ 正文 ≤ 3.5
- 不许藏：与本页 message 直接相关的内容（论述对象、结论、图表标题、序列名、关键时间与数字）不得用小字
  - kicker 只放范围、日期、口径这类说明（如「2026 年 Q2 数据」）；承载结论或论据的句子升为 conclusion，用小标题级
- 密度低 → 所有层级一起放大，包括大标题，不是只放大一个；小字号只在重页用，且只给不重要的说明文字
- 正文内个别数字 / 关键词可加粗 + accent，一个模块最多一处
- Bold 慎用：大标题同款粗体只给 title、大数字和一句话页的那句话；小标题、结论句用 Medium，正文里除数字与个别关键词外不用 Bold [W]
- 高亮要有对照才成立
  - 同一组并列元素里，「加粗 + 高亮」只能落在一个成分上：如「客户 A - 家电」里只有类型（家电）用 accent，「客户 A -」用深色；不能整组小标题全部加粗 + 高亮。其余成分靠换颜色、降字号或降字重退后
  - 分支信息（如一对数据 30% → 60%）可以用小标题字号，但不用高亮色；它不是第一层级
  - 页面有重点组件（如推荐方案）时，高亮色全部集中在它身上：其余组件的小标题、bullet 圆点、数字都不用 accent
  - 高亮色已经用在小标题上时，icon / 配图必须降噪（深色或冷色调），见 11 Icon Style
- 组件内要紧凑、也有层级：互相解释的元素（如占比图 + 60%）是一组，间距取 g，不拉开；组内图最大、第一眼看到，数字其次。窄长区域里上下排列，上下的文字相应收窄居中（宽度不必严格一致）
- 不重复大标题 [M]：除 title 外，任何小标题级以上的文字与 title 的 2-gram Jaccard ≥ 0.6 → 失败（14 C-11）
- 元标签不上页面：「结论先行」「核心观点」「背景」「小结」这类只说明页面功能、不含信息的词，不做 title 也不做 kicker

### Information Density

- 内容过多：删 → 合并 → 拆页 → 最后才考虑缩小
- 不通过压缩字号解决信息过载；单页上限 480 个汉字（英文 240 words），超出必须拆页 [M]
- 密度分档（初始阈值，按误报率调；英文按 words 计，阈值减半）
  - 轻：body ≤ 120 字（英文 ≤ 60 words），元素 ≤ 8
  - 中：121–300 字（61–150 words），或 9–20 元素
  - 重：301–480 字（151–240 words），或 > 20 元素
  - 元素 = 独立文本框、形状、图表、图片；表格计 1 + 行数 / 4；等距横排的并列组（n ≥ 3）同样按 1 + n / 4 计；紧贴对（数字 + 释义、icon + 要点）算 1 个，作为要点符号或条目配图的 icon 不单独计数
  - 密度档决定本页的正文起始字号（见 Whitespace、14 S-01），是页面所有尺寸决策的起点
- 全 deck 密度节奏，按字数和元素数算
  - 连续三页不得都是高密度 [M]；连续三页同档（含轻、中）[W]
  - 重页 ≤ 内容页总数的 40% [M]
  - 每个重页之后 2 页内必须出现轻页或中页 [M]
  - 前 3 页内至少 1 个轻页，末 2 页内至少 1 个轻页 [W]
  - 一句话页（statement）和章节页按轻页计入节奏序列；封面、目录、结束页不计。一组系列页在「连续 N 页」这类滑动窗口里算 1 页
- 副标题和结论行降为可选项，不是必须
  - 带副标题的内容页 ≤ 60%，且不得连续 4 页都有 [M]
  - 结论行允许出现在 body 内任意位置，不钉在底部；连续带结论行 ≤ 2 页，全 deck ≤ 50% [M]
  - 标题已是结论式时，结论行不得复述标题 [J]
- 控制页面视觉元素数量
- 文本容器
  - 默认容器 = 无；分组靠留白（见 Whitespace）和对齐。形状容器的使用要节制，但不是不能用
  - 三类容器，各管各的事
    - 小（圆形 / 胶囊，`tag`）：小标题、items、属性
    - 中（圆角矩形描边或填充，`card:N`）：页内多种元素的分组；对比类优先用不同颜色的描边框
    - 大（直角矩形，`panel:region` 或全页 `bg`）：区域背景
  - 同页允许 小 + 中 或 小 + 大；中 + 大不同页出现 [M]；大容器每页 ≤ 1 [M]；中容器只框需要分组或对比的那部分，不把所有元素都框起来 [J]
  - 单页中容器样式 ≤ 1 种（描边框 / 填充块 / 分隔线三选一，或无）[M]；`tag` 与 `panel:region` 不计入
  - 整套 deck 内容页中，无任何描边框与填充块的页面 ≥ 1/3 [M]
  - 描边框只在三种情况允许 [W]：≥ 3 个多行组且靠间距无法区分；表达「选中 / 推荐」状态（仅选中项带填充）；对比双框（优 / 劣、前 / 后，两框不同颜色）
  - 同页卡片数 2–6（2 只用于对比 / 优劣）；相邻两页都用卡片时数量必须不同 [M]
  - 方案 / 选项类允许全部用填充卡：推荐项用 tertiary 浅色，其余用中性浅灰；不给普通正文段落套填充块 [J]
  - 对齐：横向排列只对齐高度，纵向排列只对齐宽度，容器大小由内容决定（14 S-04）
  - 区域背景 `panel:region`：页面能分成两大组内容（如论据 / 结论）且两组都有可视化元素时使用
    - 直角，必须三边贴住页面边缘 [M]，第四边位置按内容定
    - 颜色与 accent 同色系：浅色（tertiary）或深色（secondary）
    - 校验时它像 bg 一样不进 S-03 内容块、S-04 贴合、S-06 对齐线；它里面的内容在贴边一侧仍守版心边距
  - `shape_language.corner` = `{small: full, medium: <锁定值>, large: 0}`

### 可视化拆解

所有信息先判断能不能拆成下面某一类，能拆就不写成段落：

| 内容 | 拆法 |
|---|---|
| 并列 / 同级分类 / 组别 | 小标题级高亮 + 语义图或 icon，视觉上体现并列（同尺寸、同位置关系）|
| 一对数据 | 大数字高亮 + 箭头或其它关系符号（30% → 60%）|
| 多组数据，占比 | Doughnut / 饼图 / 单条 bar 组成图 |
| 多组数据，趋势 | Column / Bar，强调趋势时加趋势线 |
| 要点 | 能列 bullet 的都列出来，不放进一段小字 |
| 时间 | 时间线（见 05）|
| 逻辑关系 | 对比 → 符号或容器颜色差异；推导 → 双箭头；包含 / 组成 → 大括号 |

### Whitespace

- 留白承担分组和强调功能，以及整个ppt的呼吸节奏
- 留白不是输入，是剩余：本 skill 不声明留白位置、不设留白比例目标。先由密度档定本页的字号档，把内容放大到位，剩下的才是留白；间距由剩余空间算出，受正文字号约束

- 尺度随密度（14 S-01）[M]
  - 密度档只定正文起始值：轻 18 / 中 16 / 重 14；其余层级按 Visual Hierarchy 的字号分级相对正文取值，各自不超过上限
  - 有余量时的放大顺序：正文 → 小标题级 → 大数字；大数字永远最后升
  - 表格 / 图片作第一层级时高度 ≥ 80% body 高；图表不受此限（小型图表只占半个版心，见 07）
  - 字号只取 type_scale 里的值；密度档是页面所有尺寸决策的起点

- 间距按剩余空间算，有上下限（14 S-02）[M]
  - g = 本页的间距单位，由 layout.py 按剩余空间算出并写进页级 manifest；0.5 × 正文字号 ≤ g ≤ 1.5 × 正文字号
  - 页内所有间距落在 {g, 2g, 3g} 的 ±20% 内：元素 / 组 / 区三级只保留比例，不保留数值；分栏间距 = 2g 或 3g
  - g 超上限说明内容太小、在撑开：放大元素，不放大间距；g 低于下限说明内容超载：拆页或降密度档，不缩字号
  - 不同关系用相同间距即不合格，读者无法从距离读出层级

- 内容块位置（14 S-03）[M]
  - 内容块 = 标题区与页码之外全部元素的墨迹框并集
  - 横向必须填满版心（左右沿 ± 1.2g），任何页都不例外
  - 竖向要么填满 body 区，要么在 body 区内居中（上下残余相等，大小不限）；顶对齐留底、底对齐留顶都不合格
  - 引言页若要底部对齐，页类型改 quote，不带内容页标题，走 09 的规则

- 容器贴内容（14 S-04）[M]
  - card / panel 的内容与容器四边的内缩 p 同页统一，p ∈ [g, 3g]；容器高度由内容决定，或内容撑满容器；容器内不得有短边 > 2p 的空矩形

- 无洞（14 S-05）[M]
  - 内容块内最大空矩形的短边 ≤ 3g（分栏间距区域除外）；留白只能在内容块之外，不能散在元素之间
  - 按行带算：元素横向占满它所在的列，洞只有「行与行之间」和「列内上下残余」两种；左对齐短元素右侧的参差、居中小容器两侧的空不算洞

- 对齐线（14 S-06）[M]
  - 页内所有顶层元素的左沿聚成 ≤ 3 条线、右沿 ≤ 3 条线；标题左沿是其中一条；容器内元素以容器内缘为基准另算
  - 列宽自由，不落固定栅格；一致的是对齐线的纪律，不是列线的位置

- 标题区下方（14 C-09）[M]
  - 标题（含可选副标题）下沿到 body 第一个元素 ≥ 3g（只有下限）

- 字数锁定（14 C-37）[M]
  - 每页正文字数 ≤ 原稿分配给该页字数的 1.1 倍，manifest 记 source_chars；排版不得改内容：填不满就居中，不加字；大数字折行时缩一档或加宽列，不换文案
  - 只允许以下四种编辑，其余照旧（不加新论点、不改数值、不删信息）
    - 从多段文本提炼小标题（每个 ≤ 10 字），不计入字数
    - 段落拆成 bullet，去掉「第一，」这类序数词和句尾标点
    - 数值的等价表达转换（6/10 → 60%），数值不变
    - 一句话页折行处的行尾标点省略

- 不填满不是目标，填满也不是目标 [J]
  - 版心是安全区；元素放大到该档字号之后剩下的空才是留白，它出现在内容块之外，聚成块，紧邻第一层级元素

### Color

- Accent Color：饱和度高的蓝色系、绿色系、紫色系；用户给了品牌色就用品牌色（可能是暖色）
  - 用于结论里最重要的数字、重点组件的短小标题、重点短结论
  - 每页的重点色要严格控制数量：一页里 accent 文字不占多数（冷色 ≤ 35%，暖色 ≤ 25%，14 C-14 [W]）；页面中段一整片都是高亮色 = 没有重点
  - 所有高亮色都要克制使用；暖色（红 / 橙 / 黄）高亮比冷色更燥，使用频率要更低
  - 饱和的高亮色不作背景色、不铺大面积：不做全屏底色、不做大色块（单个 accent 填充形状 ≤ 8% 页面面积，14 C-14 [M]）；章节页、区域背景、卡片都用低饱和色
  - 数字旁的释义、单位说明、论据数字不用 accent；需要颜色区分时用 secondary（同色系深色）
- Secondary Color: 与accent color同色系的低明度低饱和度的深色，视情况可以有多级深色
  - 用于长小标题、重点长句结论
  - 深色矩形方框容器、胶囊容器
- Tertiary Color: 与accent color同色系的高明度低饱和度的浅色，接近白色
  - 浅色矩形方框容器、胶囊容器
  - accent 是暖色时，区域背景这类大面积用色要再降饱和度、降色温（偏米白 / 灰白，不是浅橙粉）：面积越大越要冷、越要灰
- Accent Light：与 accent 同色系的浅亮色，只用于深色背景 / 深色遮罩上的高亮（palette 的 `accent_light`）
- Data Muted：与 accent 同色系的低饱和灰度色，图表里的论据 / 参照序列、目录序号用（palette 的 `data_muted`）
- Neutral 里的深灰用于「劣势」一类的对立面
- 以上都写成与 accent 的关系，不写具体色名；hex 由每套 deck 的 palette 决定
- 高亮色为结论服务：论证对象用 accent，论据、参照用辅助色
- 同层级信息避免无理由多色
- 灰度测试仍应保持层级



### 一致性

- 一致性通过accent color、字体、视觉元素风格来体现，不通过相同的模板 / 排版
- 页间一致靠大标题位置与样式、色彩、字体；单页内的排布丰富度才是信息可视化，不要为了统一把该强调的信息压进小字
- 分两层
  - 锁定层（全 deck 不变）：色板、字体与字号刻度、形状语言、描边、圆角、对齐线纪律、图片处理、icon 风格、页码位置（≤ 20 页不放页码）、大标题位置与字间距。在 11-style-system 阶段决定，之后一个都不改
  - 变化层（相邻页必须不同）：body 模式、第一层级形式（focus.form）、密度档、容器样式、列数与列比，即 manifest 里的五项
- 大标题位置是页面层唯一固定位置的元素；具体位置由视觉方向决定，一旦决定全 deck 不变 [M]
  - 例外只有配图方式 3 / 4 / 5 / 6（见 11 配图方式）：标题位置由配图方式与图片所在边决定，同一方式同一位置，manifest 用 `title_pos` 声明，校验器按 14 的规则核对；无图页和配图方式 1 / 2 / 7 一律用基准锚点

- 相邻页禁止相同body模式，除非是同一大标题下相同结构的内容（比如几个类别的目标用户分析，团队成员介绍....）

  - 同一大标题下相同结构的内容应该用相同的layout，否则会产生不必要的理解成本
  - 这类系列页在 manifest 标 series，不受下面两条变化规则约束；系列页合计 ≤ 内容页的 40%，超过先考虑合并为总览页 + 分页 [W]

- 相邻两页 manifest 五项（pattern / focus.form / density / container / columns）中至少两项不同 [M]；contrast、image 不参与比较
- 相邻页图表 / 图片左右交替 [W]：上一页视觉元素在左，下一页放右；series 页豁免。校验器读 `image.side` 与 `visual_side`
- 页码不是必须：≤ 20 页不放；> 20 页放右下锚点 [M]
- 任意连续 5 页内，同一 body 模式出现 ≤ 2 次 [M]
- 同一内容类型（02–08）在不同密度档下必须有不同实现：至少一个有框版 / 无框版，一个紧凑版 / 放大版。选哪种由本页密度档决定，不由上一页决定
- 变化必须由内容逻辑驱动：结构由内容类型决定，尺度由密度档决定；无理由的变化是随机，不是设计 [J]
